# OURSPOT — 10분 이내 무편집 최종 재촬영용 명령어 시트 (final2)

> **사용법:** 위에서 아래로 진행한다. **각 코드 블록 전체를 복사 → VS Code의 Ubuntu Bash 터미널에 붙여넣기 → 결과 확인**한다. 명령어를 암기하거나, 터미널을 옮긴 후 변수·함수를 수동으로 복구할 필요가 없다. 각 명령 블록이 **촬영 설정 파일을 자동으로 다시 불러온다.**
>
> **재촬영 전용:** `demo-113-final2` / Ubuntu 포트 `8286` / Mac Chrome `http://127.0.0.1:8286/login.html`. 이전 연습 환경 `demo-113-a`(8283), `demo-113-film`(8284), 운영 환경 `ourspot-*`(8080)과 **서로 다르다.**
>
> **촬영 조건:** 교수님의 추가 공지에 따라 **10분 이내, 무편집·연속 화면 녹화**. 기존 3분 시간표는 적용하지 않는다. 6개 서비스는 **각각 별도의 `docker run` 명령으로 직접 실행**한다. Docker Compose를 사용하지 않는다.
>
> **출처:** [Codex 원본 시연 가이드](https://github.com/baeys0619/ourspot/blob/main/docs/verification/demo-command-sequence.md). 기존 검증 구조를 유지하면서 실제 연습에서 확인한 Bash 변수 유실, 운영 서버 주소 혼동, 장소 이름 불일치에 대응하도록 수정했다.

## 0. 녹화 **전** 준비 — 영상에 넣지 않아도 됨

> **중요 — 기존 촬영 실패 환경 재사용 금지:** `demo-113-final`(포트 8285)은 A1~A3에서 일부 생성된 리소스가 남아 있으므로 사용하지 않는다. `demo-113-final2`(포트 8286)로 새로 시작한다. 기존 테스트 환경이나 운영 `ourspot-*`를 삭제·재시작하지 않는다.
>
> **메모리 확인:** 이번에는 4GiB Ubuntu VM에서 테스트 컨테이너 누적으로 SSH 연결이 끊어졌었다. 촬영 전에 `free -h`, `uptime`으로 메모리 및 부하를 확인하고, 이상하면 A1을 시작하지 않는다. 본 파일은 녹화 전에 별도의 새 Docker 리소스를 생성하지 않는다.

### 0-1. Ubuntu 사전 준비 (처음에 **한 번만**)

- VS Code에서 Ubuntu SSH 터미널을 연다. **이전 연습용 `demo-113-film`의 컨테이너·네트워크·볼륨은 삭제하거나 재사용하지 않는다.**
- 아래 블록을 **녹화 시작 전** 통째로 실행한다. 영상에서 실행할 변수·함수를 **비밀정보가 없는 촬영 설정 파일**에 저장한다. 터미널이 바뀌어도 A~D 명령 블록에서 자동 복구한다.
- `READY: ...`가 나오지 않으면 **녹화하지 말고 오류를 확인**한다. 이 블록은 시연 컨테이너·네트워크·볼륨을 **만들지 않는다**.


### 0-2. Mac SSH 포트 전달 (Mac의 **일반 터미널**)

- 먼저 Mac에서 `lsof -nP -iTCP:8286 -sTCP:LISTEN`으로 **Mac 8286을 누가 사용 중인지 확인**한다. VS Code가 `8284 → 8286`처럼 잘못 전달하고 있다면 **VS Code의 PORTS 탭에서 잘못된 전달만 중지**한다. Ubuntu 8286은 A11 전까지 열리지 않는 것이 정상이다.
- **기존 8285 SSH 터널은 8286 연결을 대신하지 않는다.** 아래 명령을 Mac 터미널 **새 창**에서 실행한다. 비밀번호 입력 후 SSH 창이 계속 점유되는 것은 정상이다.

- 아래 명령어를 실행한 Mac 터미널을 **촬영이 끝날 때까지 열어 둔다.** 이미 8286가 전달 중이면 중복 실행하지 않는다.

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8286:127.0.0.1:8286 yunsun@192.168.64.7
```

### 0-3. Chrome과 화면 준비

- **녹화 시작 전에 반드시 0-1의 `READY: ...final2, port 8286, context saved` 확인.** 기존 `final` 폴더 안에 있는 촬영 설정 파일은 사용하지 않는다.

- [ ] Chrome **새 시크릿 창**을 열어 두고, 로그인할 때 **반드시** `http://127.0.0.1:8286/login.html`을 입력한다. **`192.168.64.7:8080`은 운영 서버이므로 영상에서 접속하지 않는다.** 컨테이너를 시작하기 전에는 8286 페이지가 열리지 않아도 정상이다.
- [ ] Chrome DevTools Console의 붙여넣기 제한이 있으면 **녹화 전에 직접** `allow pasting`을 입력하고 Enter를 눌러 해제한다. 타인의 불명확한 코드는 붙여넣지 않는다.
- [ ] 사용자 A/B의 **서로 다른 시연 전용 비밀번호**를 준비한다. 코드 파일, 영상, 브라우저 자동완성 목록에 비밀번호를 노출하지 않는다.
- [ ] VS Code 위쪽은 이 시트, 아래쪽은 Ubuntu 터미널로 배치한다. **터미널을 바꿔도 괜찮다.** 각 Bash 코드 블록 **맨 앞의 `source` 줄까지 포함해 통째로 복사**해야 한다.
- [ ] 명령어를 붙여넣은 뒤 출력이 완전히 끝난 것을 확인하고 다음 블록으로 넘어간다. **STOP, ERROR, FAIL이 나오면 이어서 촬영하지 않는다.**

## A. Docker 생성 — `docker run`은 **각각 개별 실행**

### A1. Bridge Network + Named Volume

### A2. MySQL — 서비스 1/6

```bash
source /home/yunsun/projects/ourspot/.runtime/ourspot-install-demo-113-final2/film-context.sh

  --restart unless-stopped --platform linux/arm64 --env-file "$runtime/db.env" \
  --mount "source=$vol,target=/var/lib/mysql" \
  --mount "type=bind,src=$PWD/database/init,dst=/docker-entrypoint-initdb.d,readonly" \
  --health-cmd='MYSQL_PWD="$MYSQL_PASSWORD" mysql -h127.0.0.1 -u"$MYSQL_USER" "$MYSQL_DATABASE" -Nse "SELECT COUNT(*) FROM users"' \
  --health-interval=5s --health-timeout=4s --health-start-period=60s --health-retries=30 \
  "$MYSQL_IMAGE" --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci --default-time-zone=+00:00
```

## D. MySQL Volume·재시작·데이터 유지 확인

### D1. Chrome — 장소 1개 저장

- Chrome Console을 닫고 **`+ 장소 저장`**을 연다.
- 권장 입력: 장소 이름 **`시연용 카페`**, 카테고리 **`카페`**. 다른 필수 항목도 채운다.
- **중요:** 실제로 저장한 이름이 `어웨이크`처럼 달라도 괜찮다. **저장 후 목록에 나타난 실제 이름을 기억하고**, D2에서 출력되는 `Before`의 이름과 일치하는지 확인한다.
- 저장된 장소가 `http://127.0.0.1:8286`의 화면에 표시되는지 확인한다.

### D2. VS Code Ubuntu 터미널 — MySQL Volume + 실제 저장된 최신 장소 `Before`

> 이전 연습의 실패 원인을 수정했다. **`시연용 카페`라는 고정 문자열을 검색하지 않고**, 이번 격리 DB에 실제로 저장된 **최신 장소 1행**을 조회한다. `Before` 값은 파일에 보관되므로 **이후 터미널을 바꿔도 사라지지 않는다.**

```bash
source /home/yunsun/projects/ourspot/.runtime/ourspot-install-demo-113-final2/film-context.sh
docker inspect -f '{{range .Mounts}}{{if eq .Destination "/var/lib/mysql"}}{{.Name}} -> {{.Destination}}{{end}}{{end}}' "$prefix-db"
demo_row > "$runtime/place-before.tsv"
if [[ -s "$runtime/place-before.tsv" ]]; then
  printf 'Before: '; cat "$runtime/place-before.tsv"
else
  echo 'STOP: no place in demo MySQL; do not restart yet'
fi
```

> 정상: `ourspot-install-demo-113-final2-db-data -> /var/lib/mysql` 및 `Before: 1  [실제 장소명]  [카테고리]`. **Chrome 목록에서 본 장소와 동일한지** 확인한다. 다르면 다음 단계로 넘어가지 않는다.
